# 11centov Implementation Plan

Goal: runnable Russian electronics storefront matching the user's detailed spec.
Architecture: App Router RSC pages compose FSD widgets and features. Entity-owned
store factories and contexts are mounted once by app/providers, never global stores.
Tech stack: Next.js 16, React 19, TypeScript strict, Tailwind 4, Zustand 5.
Spec: user's full specification in this chat; proceeding directly as requested.

## Global constraints

- Imports descend app → pages → widgets → features → entities → shared.
- Public index.ts APIs; no cross-slice imports on one layer.
- Secrets server-only. Catalog API contract not yet verified; explicit USE_MOCK.
- Telegram failure must never be displayed as order success.

## Tasks

- [x] Shared foundation, tokens, accessible overlay and form primitives.
- [x] Typed catalog adapter and mock products, categories, isolated cart/favorites stores.
- [x] Interactive features: variants, cart, favorites, comparison, themes, order form.
- [x] Header, drawer, server product grid, hero and footer; all routes.
- [x] Order validation and server-authoritative prices, escaped Telegram HTML.
- [x] Typecheck, unit tests, FSD import check, production build, browser review.

## Implementation rulings and review

- Next requires framework app/pages at one level. Root app has logic-free bridges
  to src/app; root pages/README prevents FSD src/pages from becoming Pages Router.
- GitLab URL returns sign-in HTML, so USE_MOCK remains enabled and DTO adapter is
  explicitly unfinished until the deployed catalog URL/contract is supplied.
- Process-local replay/rate guards are suitable for local single-process testing;
  README requires a durable repository before multi-instance production.
- Independent review found lost timeout guard across navigation and pending cart
  mutation loss. Fixed with persisted non-PII attempt status and mutation lock;
  regression tests added. No real Telegram message sent without credentials.

## Review focus

- Refresh persistence without SSR hydration mismatch or shared cart state.
- Unavailable backend and missing Telegram credentials have actionable errors.
- Client cannot substitute product prices or quantities into an order.
- Mobile menu, drawer focus, no-results and empty cart states.
- Form retry does not automatically resend an ambiguous Telegram request.
