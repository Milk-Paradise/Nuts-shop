# Production YooKassa

Документ описывает безопасное включение уже зарегистрированного провайдера `yookassa`.
Реквизиты магазина не хранятся в Git, `.env` репозитория или Jira.

## Предварительные условия

- production backend доступен по HTTPS;
- в окружении задан `PAYMENT_PROVIDER_CONFIG_ENCRYPTION_KEY` — base64-ключ ровно на 32 байта;
- в кабинете YooKassa доступны идентификатор магазина и секретный ключ;
- webhook URL доступен извне по HTTPS на порту 443 или 8443;
- в кабинете YooKassa включены уведомления `payment.waiting_for_capture`, `payment.succeeded`, `payment.canceled` и `refund.succeeded`.

## Настройка

1. Открыть в production Admin раздел «Способы оплаты».
2. Выбрать «ЮKassa» → «Настроить».
3. Ввести `shop_id` и `secret_key` через защищённую сессию администратора.
4. Выбрать режим «Боевой» и сохранить.
5. Убедиться, что в ответе и интерфейсе отображаются только `shop_id`, режим и признак сохранённого ключа. Сам ключ не должен возвращаться.
6. Включить провайдера переключателем. Сервер повторно проверит реквизиты через `GET https://api.yookassa.ru/v3/me`; при ошибке провайдер останется выключенным.

## Webhook

URL:

```
POST /hooks/payment/yookassa_yookassa
```

В кабинете YooKassa указать полный HTTPS URL этого маршрута. Redirect после оплаты не считается подтверждением оплаты: сервер сверяет актуальный статус через API YooKassa при проверке статуса витриной или при обработке webhook.

Для совместимости с текущей витриной `POST /store/catalog/payment/status` принимает в поле `cart_id` как ID корзины, так и ID созданного из неё заказа. В обоих случаях проверка выполняется для исходной корзины и её платёжной сессии.

Если backend находится за reverse proxy, передать доверенные CIDR proxy в `YOOKASSA_WEBHOOK_TRUSTED_PROXY_CIDRS`. Если backend принимает соединение напрямую, оставить переменную пустой.

## Проверка после включения

1. Создать заказ с провайдером YooKassa и перейти по URL подтверждения.
2. Убедиться, что до webhook заказ не становится оплаченным.
3. Завершить тестовую оплату согласованным способом и проверить переход заказа в оплаченный статус после webhook.
4. Повторить тот же webhook: повторная доставка не должна создать второй платёж или второй заказ.
5. Выполнить полный возврат, затем отдельный частичный возврат, если способ оплаты YooKassa его поддерживает. Перед каждым возвратом оператор подтверждает действие в админке.
6. Проверить, что ошибка YooKassa оставляет заказ неоплаченным и позволяет покупателю повторить оплату с сохранённой корзиной.

## Отключение

При инциденте выключить провайдера в разделе «Способы оплаты». Новые платежи перестанут создаваться, а чтение статусов и обработка уже созданных платежей сохранятся для разборов и сверки.
